# F2 — Golden, canales y runner con el núcleo del ZIP

## Objetivo

Crear contenedores locales con el mismo motor distribuido.

## Precondiciones

F1 verde, usuarios creados, Incus operativo y acceso de administración.
Todavía no hay logins de agente dentro del golden ni de los clones.

## Pasos

El envoltorio pasa un entorno cerrado, TC_FLAG_POOL_SIZE (no existe flag
--pool-size en provision.sh), plantillas git del cuestionario y TF_REPO_URL
vacía. Usa --only disk, network, golden y clone; nunca ejecuta intake.
El golden incluye el motor en /home/CUSER/motor-paquete; no exige git en el
motor del ZIP. Para satisfacer esa precondición crea un snapshot git local
del núcleo, sin remoto ni descarga y con identidad neutra solo en el commit.
Usa tar del núcleo, sin perfiles, ledger, env ni respuestas.
Los canales y el runner heredan esa copia. Nunca usar --force-golden.

Enseña el plan, espera el visto bueno y deja la acción a la persona:

```bash
bash "$PKG/instalacion/scripts/f2-provision.sh" --plan
! sudo bash "$PKG/instalacion/scripts/f2-provision.sh" --ejecutar
! sudo -v
```

sudo -v habilita las consultas privilegiadas durante los checks iniciales.
El operador pertenece a incus-admin; no se propagan credenciales de agente.
El runner nace del golden y es contenedor de ejecución, no una cuenta adicional.

## Comprobación

La plantilla puede estar encendida al terminar su construcción. El envoltorio
consulta su estado antes de arrancar o parar y siembra el motor si falta la
marca de sembrado o cambia la huella de NUCLEO.sha256. Verifica los hashes
antes de marcarla terminada; con clones y una huella incorrecta se detiene.
Después de un corte se puede repetir la ejecución aprobada. Si la construcción
quedó incompleta, el skill no dejó su marca base-completa y el envoltorio
exige recuperación antes de sembrar o clonar. Si fue por una credencial
rechazada, vuelve a F1 primero:

```bash
bash "$PKG/instalacion/scripts/estado.sh" reabrir F1
bash "$PKG/instalacion/scripts/check-F1.sh"
bash "$PKG/instalacion/scripts/f2-provision.sh" --plan-recuperar
```

Muestra ese plan y espera el visto bueno. La persona ejecuta después:

```bash
sudo bash "$PKG/instalacion/scripts/f2-provision.sh" --recuperar
sudo bash "$PKG/instalacion/scripts/f2-provision.sh" --ejecutar
```

La recuperación borra solo golden del proyecto declarado, sin marca de
terminación y sin canales, runner ni pozos de esta instalación. Rechaza
plantillas completas, nombres ajenos y cualquier clon existente.

```bash
bash "$PKG/instalacion/scripts/check-F2.sh"
```

Verifica estados STOPPED/RUNNING, hashes host contra cada canal y runner,
y verify.sh --etapa creado antes de logins: no lee el registro, exige modelo
vacío y anuncia que su preparación queda pendiente de F5. Un modelo fijado
antes de preparar el canal es rojo. Las demás comprobaciones siguen activas.
La etapa es una opción explícita de CLI y no es el mecanismo TC_VERIFY_SCOPE.
Los tres modos son: sin argumentos (histórico: registro vigente y canales sin
credenciales), creado (F2: modelo vacío, sin registro ni credenciales) y
acreditado (F5: modelo vigente exacto, logins permitidos en canales, golden sin
credenciales). preparado se conserva como alias público del histórico.
Ejecuta siempre check-F2 o check-F5 desde la terminal del instalador: estos
checks proporcionan el entorno cerrado de la instancia al verificador.
Un contenedor existente incompleto
permanece rojo; no se borra automáticamente.

## Remediación

| Diagnóstico | Acción |
|---|---|
| contenedor ausente o estado | Revisar incus list con el operador; repetir el plan y la ejecución aprobada. |
| núcleo: hash distinto o ausente en contenedor | Detener; comparar con ZIP íntegro; no adoptar hashes del contenedor. |
| núcleo local inválido | Volver a F0 con estado.sh reabrir F0 y obtener paquete íntegro. |
| contenedor ausente o estado / consulta sudo o incus rechazada | La persona renueva sudo -v, confirma grupo y acceso al daemon. |
| verify.sh FAIL | Corregir exactamente el ítem mostrado usando el skill talent-channels; no TC_VERIFY_SCOPE. Si falla modelo vacío, restaurar la plantilla íntegra: no resolver ni fijar modelos en F2. Repetir check-F2, que usa creado con entorno cerrado. F5 prepara y verifica el modelo vigente con acreditado; el histórico (alias preparado) se reserva al aprovisionamiento y exige canales sin credenciales. |
| plantilla sin marca correcta con clones | Detenerse y conservar clones; revisar recuperación con la persona. No destruir clones. |
| recuperación: plantilla completa | Se rechaza el borrado; conservar plantilla terminada. |
| recuperación: plantilla de esta instalación ausente | Confirmar proyecto y nombre; nunca borrar una plantilla ajena. |
| golden existente incompleto | Mostrar --plan-recuperar, aprobar y ejecutar --recuperar; repetir --ejecutar. No clonar una construcción parcial. |
| runner perfil/preflight/repositorio | Revisar perfil runner, usuario de gates sin sudo, repositorio sano y cero credenciales en todos los homes; repetir F2. No borrar credenciales ajenas automáticamente. |

## Al terminar

Golden parado, N canales y un runner vivos con el motor íntegro y sin logins.
El runner declara perfil runner en channel-profiles.list: usuario de gates runner
en docker, sin sudo, repositorio /home/runner/repo con origin público del cuestionario,
sin credenciales ni descarga. check-F2 exige correspondencia de origin y ausencia
de credenciales en el entorno, sin mostrar sus valores.
check-F2 ejecuta el mismo scripts/lib/preflight.sh que el launcher del motor,
barriendo todos los homes. Un runner con credenciales queda rojo.
