# F8 — Un cambio pequeño por el proceso completo

## Objetivo

Demostrar issue → plan-gate → código → auditoría → handoff → merge → Done.

## Precondiciones

F7 verde. Canal, coordinador y estación M1 operativos. La issue cambia exactamente
un fichero Markdown bajo docs/. No usar --no-linear, --soft ni exenciones del revisor.
La persona trabaja en la terminal del instalador salvo donde se indique C1.
El paquete debe ser legible por C1 para ejecutar el ayudante de conservación.
Las rutas y valores siguientes son ejemplos: sustituirlos por los del montaje.

## Pasos

1. **Persona, terminal del instalador.** Crear la issue en el equipo y proyecto
   declarados mediante linear-skill y talent-issue-craft. Conservar la respuesta
   de Linear (identificador, título y fecha de creación). Puede recuperarse
   también después del trabajo, aunque la issue ya esté Done:

<!-- terminal: instalador -->
```bash
PKG=/srv/fabrica/talent-factory
CLON=/srv/producto
ISSUE=ABC-1
PROYECTO=ejemplo
CARRIL=11
C1=ejemplo-c1
HOME_C1=/home/ejemplo-c1
bash "$PKG/instalacion/scripts/f8-originales.sh" "$ISSUE"
```

2. **Persona → torre del coordinador.** Imprimir y pegar el encargo completo.
   El ayudante sustituye proyecto, issue, canal y directorio de evidencias.
   Solo el coordinador ejecuta dispatch.sh, desde su clon y su identidad.
   Al terminar, el coordinador conserva con el ayudante de su identidad.
   Copia sin modificar el .norm de la última ronda a plan-normalizado.norm y
   audit-last del carril a audit-last.env en su directorio de evidencias.
   Deja veredicto-plan.txt, informe-parada.md y veredicto-codigo.txt íntegros.
   Los veredictos son objetos JSON GO sin bloqueantes: plan con sha256 del .norm;
   code con head completo y run_id igual al registro. El informe empieza por
   STOP-AUDIT — ISSUE y declara SHA auditado: seguido del head completo. No inventar aprobación.
   Si la organización exige una línea final del PR para evitar revisión automática,
   declararla mediante --linea-pr 'texto literal acordado' en esta orden.
   Si no se declara, desactivar la App o aceptar explícitamente el gasto adicional
   advertido en F4 antes de retirar el borrador. cr-review solo habilita el respaldo.

<!-- terminal: instalador -->
```bash
bash "$PKG/instalacion/scripts/f8-encargos.sh" "$ISSUE"
```

   El encargo pide al coordinador ejecutar en su terminal:
   `bash "$PKG/instalacion/scripts/f8-conservar.sh" "$ISSUE" "$PROYECTO" "$CARRIL"`.

3. **Persona, terminal del instalador.** Cuando el coordinador devuelve el PR
   validado, conservar el verificador real mientras sigue OPEN y en borrador.
   El comando guarda .json y .log privados por issue/PR/head/ordinal. Un rojo
   detiene el flujo; corregir y repetir la misma orden con el PR aún en borrador.
   El head verificado debe mantenerse hasta el merge; si cambia, verificar otra vez.

<!-- terminal: instalador -->
```bash
PR=1
bash "$PKG/instalacion/scripts/f8-handoff.sh" "$PR" "$ISSUE"
HANDOFF_REAL=/srv/evidencias/handoff-verificado.json
```

HANDOFF_REAL es la ruta que imprimió f8-handoff para el mismo head.
Los valores del bloque son ejemplos: sustituye HANDOFF_REAL por esa ruta exacta.


4. **Persona → torre M1.** Imprimir y pegar el encargo de estación. M1 aplica
   gates AND, revisión, fusión y Done; sella hitos y bloqueos en el bus. Ante rojo
   se detiene. Observar el bus con su lector sin volcar entorno ni credenciales.

<!-- terminal: instalador -->
```bash
bash "$PKG/instalacion/scripts/f8-encargos.sh" "$ISSUE" "$PR"
```

5. **Persona, terminal del instalador.** Tras fusión y Done, consultar los
   originales merge.json e issue-done.json. issue.json conserva identificador,
   título y fecha de creación; si falta, esta misma orden lo genera.
   El ayudante usa cabecera temporal 0600 en escrow y la elimina aun ante error;
   nunca pasa el token como argumento ni lo imprime.

<!-- terminal: instalador -->
```bash
bash "$PKG/instalacion/scripts/f8-originales.sh" "$ISSUE" "$PR"
```

6. **Persona, terminal de C1, panel del canal.** Capturar los cinco estados
   con el capturador y parser reales instalados. PKG es el paquete legible por C1;
   CLON es su clon de producto. Usar el CARRIL adjudicado, nunca el contenedor.
   Desde la terminal del instalador, leer los nombres públicos del cuestionario
   y entrar al panel del canal como su usuario, mediante el operador de Incus:

<!-- terminal: instalador -->
```bash
R="$(sed -n 's/^respuestas=//p' "$PKG/instalacion/estado/contexto.conf")"
OPERADOR="$(sed -n 's/^usuario_incus=//p' "$R")"
CUSER="$(sed -n 's/^cuser=//p' "$R")"
CONTENEDOR="vibe-channel-$CARRIL"
sudo -H -u "$OPERADOR" incus exec "$CONTENEDOR" -- su - "$CUSER" -c 'tmux attach -t v'
```

   Seleccionar el panel desarrollador v:.0 con Ctrl-b q y su número 0 si hace
   falta. Ctrl-b d desacopla sin cerrar la sesión ni detener el turno.
   Teclear los estados en ese panel; ejecutar las capturas en otra terminal
   de C1 (sudo -iu "$C1" desde la terminal del instalador).
   Antes de cada orden provocar el estado indicado en el panel v:.0:

   - Reposo: después de terminar y conservar el ciclo, teclear /clear en el CLI
     del canal y pulsar Enter. Esperar el prompt y compositor completo, sin
     cuentas/hashes. Esta limpieza corresponde solo a la calibración del canal;
     no se usa en las torres ni durante el ciclo o ante un safeguard.
   - Menú: abrir /model, dejar visible el selector, capturar modal y cerrar con
     Escape sin cambiar modelo. En Codex abrir el selector equivalente /model.
   - Ocupado: pegar esta orden de una sola línea: «Ejecuta en primer plano con la herramienta Bash: python3 -c "import time; time.sleep(40)" y despues responde solo: terminado».
     Mantiene la herramienta en ejecución 40 segundos, sin ficheros ni red.
     Si pide permiso, conceder solo esa herramienta. Capturar busy a los
     6 segundos de iniciada.
     Si la herramienta es bloqueada, detenerse y conservar el diagnóstico;
     no eludir la restricción ni declarar ocupado un panel en reposo.
     Un turno que solo escribe texto no mantiene la línea de actividad.
   - Terminado: esperar que esa herramienta y el turno terminen; capturar done.
   - Redibujado: con compositor completo visible, capturar redraw; el capturador
     obtiene de esa pantalla real un recorte no vacío clasificado desconocido (rc 2).
     No añadir texto ni simular un redimensionado fugaz.

<!-- terminal: C1 -->
```bash
PKG=/srv/fabrica/talent-factory
CLON="$HOME/producto"
PROYECTO=ejemplo
CARRIL=11
EVIDENCIAS="$HOME/evidencias-fabrica/$PROYECTO"
```

   Ejecutar cada orden individualmente en el momento indicado.
   Un estado mal clasificado se descarta antes de escribir destino. Si existía
   una captura rechazada, volver a provocar el estado y añadir --repetir a su
   orden; conserva la anterior como estado.rechazada.* y publica solo la nueva
   captura clasificada. Un secreto/cuenta nunca se conserva como captura aceptada.
   Repetir los cinco estados en v:.1 si el auditor tiene otro par CLI/versión;
   para Codex cambiar TCO_PANE_CLI_VERSION_CMD a
   'codex --version | grep -oE "[0-9]+\.[0-9]+\.[0-9]+" | head -n 1'.
   No reutilizar fixtures sintéticos para acreditar UI.

   El estado sigue siendo privado 0700; C1 no escribe en él. El importador permite
   únicamente los originales fijos y las cinco capturas por par. Lista incidentales
   como no importados; rechaza enlaces, escapes, tipos especiales y originales
   vacíos, nombrando el fichero. Nunca modifica originales ni recibos existentes.

   par recibido. Los originales existentes distintos siguen siendo rojos.

9. **Persona, terminal del instalador.** Registrar cada par en su propia
   identidad, repitiendo la orden para Codex si aplica. El check vuelve a contrastar
   versiones instaladas, registro, scanner y clasificación, sin override de versión.

<!-- terminal: instalador -->

10. **Persona, terminal del instalador.** Generar los siete recibos y el ciclo.
    El ayudante genera solo los recibos ausentes a partir de los originales fijos
    y del último handoff verde del mismo head. No crea el trabajo ni la aprobación.
    Conserva autor de custodia, rutas definitivas y hashes.
    Los ayudantes copian los artefactos, calculan hashes y rutas definitivas, y rechazan
    originales vacíos, de otra issue o destinos existentes distintos. Para custodia manual
    sigue disponible f8-recibo.sh ETAPA ARTEFACTO AUTOR con ruta absoluta.
    Etapas/resultados: issue/CREADA, plan-gate/GO, codigo/DOCS, auditoria/GO,
    handoff/PASS, merge/MERGED, Done/Done. Originales vacíos, alterados, ajenos,
    veredicto vigente NO-GO, SHA truncado o commit distinto dejan el ciclo rojo.
    Solo cuentan objetos JSON de primer nivel ligados al digest del plan o al run_id
    del registro de código; los ejemplos anidados no acreditan ni delimitan un objeto
    ilegible. Toda clave verdict fuera de un diccionario de primer nivel leído
    (también en listas) deja rojo salvo vínculo completo que demuestre otra ronda;
    las rondas ajenas y las palabras de la prosa no deciden la aprobación.
    Los cortes del panel y CRLF se toleran al analizar, con hashes sobre bytes conservados.

<!-- terminal: instalador -->
```bash
export F8_ISSUE="$ISSUE" F8_PR="$PR"
bash "$PKG/instalacion/scripts/f8-ciclo.sh"
```

## Comprobación

    originales y recibos, exige handoff real en borrador y contrasta en vivo
    MERGED, mismo head/merge, único fichero docs, magic word de la issue, local-gates
    sobre ese head y Done en Linear. Un status verde de otro commit no sirve.

<!-- terminal: instalador -->
```bash

```

## Remediación

Ante cualquier rojo, conservar diagnóstico y detener el tramo dependiente.
Nunca recalcular hashes para ocultar una sustitución ni rellenar éxitos ausentes.

| Diagnóstico | Acción |
|---|---|
| humo: esquema / issue / PR/head / ruta/digest inválidos | Corregir únicamente metadatos contra artefactos reales; no inventar OID. |
| humo: tramo sin evidencia / archivo vacío | Volver al tramo pendiente del proceso; no declarar cierre. |
| humo: evidencia vacía o hash distinto | Conservar los dos artefactos, aclarar su procedencia; no recalcular para ocultar sustitución. |
| humo: merge/head sin confirmar | M1 resuelve gates y merge del mismo head; PR abierto no es verde. |
| humo: debe cambiar un fichero de docs | Usar issue de humo acotada; no aceptar cambios de producción. |
| humo: gates remotos ausentes o rojos | Completar el posteo real de los gates y corregir fallos; no sustituir por rc local. |
| humo: Done sin evidencia Linear | Obtener respuesta de la issue correcta tras cierre confirmado. |
| consulta gh o datos ilegibles | Restaurar login/permisos y volver a consultar, conservando artefactos. |
| capturas ausentes, versión inválida o clasificación | Capturar idle, busy, done, modal y redraw de la versión instalada y calibrar sus regex; no declarar idle un estado desconocido. |
| original ausente/vacío/sin binding o aprobación | Conservar el artefacto real del tramo correcto con autor y issue/PR/head; no rellenar éxitos. |
| artefacto original ausente/vacío/hash distinto/de otra issue | Recuperar salida original íntegra de la issue de humo y su registro de procedencia; no fabricar un JSON de éxito. |
| resultado verify-handoff ausente / comando rc del verificador | Recuperar la verificación del borrador del mismo head; no ejecutarla sobre un PR fusionado ni fabricar el registro. |
| registro/versiones/capturas no coinciden / capturas sintéticas | Capturar cada CLI/versión instalada, clasificarla y registrar la lista real con separador vertical. |
| PR no liga la issue / local-gates no acreditado sobre head | Corregir magic word y publicar gates ejecutados sobre ese head, sin inventar status. |

## Al terminar

Nueve fases verdes y evidencia de un ciclo completo; entregar rutas y resultados.
La fábrica funciona; certificación del repo PENDIENTE hasta DESPUES-certificacion.md.
